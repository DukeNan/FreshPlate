## 3. 驳回与降级项（记录理由，避免回归）

- **「补齐方向使饱和上界论证失效」——撤回，不成立。** 修订前公式集内的 piece→ml 本就可合法输入达到 10^21（`10^9 × 10^12 / 1`），张力与补齐方向无关；cap 的正确性论证从不依赖 10^15 是任何方向的最大值，只依赖 cap 大于 need 上限与向下夹取。
- **「10^15 括注是数学错误」——撤回，不成立。** 原句明确限定范围为 piece→g 与 g→ml 两方向，在该范围内为真（两方向上界确为 10^15）；其问题只是作为 cap 选择依据有误导性，已删除。任何把它改写为「六方向共同上界」的做法都会引入真实的数学错误（全局上界是 10^21），修订已正确避免。
- **「聚合饱和契约未定义」——降级。** 输出契约（聚合真实值 ≥ cap 时饱和到 cap）在修订前的方案中已存在；本次修订补充的是累加算法的防溢出说明（§2 第 4 项），属完善而非补缺。
- **查询校验落点与文档索引——文档整理项，非契约缺口。** 参数校验契约（400 `INVALID_ARGUMENT`、q 码点上限、分页上限）修订前已在 §3.3/§4 完整规定；落点函数名与 README/IMPLEMENTATION_PLAN 的链接属整理。`AGENTS.md` 的 recommendation planned 状态本就正确，未改动；`docs/test/IMPLEMENTATION_SUMMARY.md` 不更新（模块未实现，不进入已交付模块表）。

## 4. 保留的折中与实施验证要求

1. **q 零命中与「命中但均不可做」在响应层不可区分——保留折中。** 空态三在 q 与 availability 同时生效时使用组合文案、不强行归因，不新增任何 q 相关计数字段（保持 stats 与筛选无关的不变量）。若实施后用户测试显示组合文案造成困惑，备选最小条款是在 `data` 下（不放入 stats）新增安全过滤与 q 生效后、availability 前的条数，用于区分两种根因；是否启用留待实施后判断，当前不实施。
2. **设计契约不等于实现正确。** 128 位乘除、阈值比较与安全累加的实际代码必须经 §8 极值用例验证后方可声称符合本契约；实现方的验证责任不因本评审免除。
3. **计数闭合依赖实现纪律。** 「每候选至多计一次」与「三项和 + 幸存者 = candidates」是 §8 必须断言的不变量；后续若新增过滤原因，必须同步扩展计数闭合，否则空态二判定失效。
4. **快照语义边界保持。** `recipe.version` 校验只保证配方一致，不保证匹配对当前库存与偏好仍准确；快照仅存前端内存，与「不持久化推荐结果」一致。实施时不得扩大 version 校验的承诺范围。
